# Sabt CRM/ERP — полный промпт системы

> Этот документ — «генеральный промпт»: полное техническое задание, по которому построена
> и развивается система Sabt (CRM/ERP SMM-агентства WeBrand, Таджикистан). Валюта — сомони (с.).
> Язык интерфейса — русский. Обновлено: сентябрь 2026.
>
> **Изменения сентября 2026:** роль «Сторисмейкер» упразднена — сторис ведут SMM-специалисты;
> раздел «Доска проектов» удалён из интерфейса (производство ведётся в «Умном календаре»);
> общий список «Проекты» скрыт — SMM работает в разделе «СММ → Проекты».

## 1. Общая постановка

Разработай веб-систему **Sabt** — CRM/ERP для SMM-агентства, которое ведёт три направления:
**SMM-сопровождение** (месячные тарифы), **разработка** (сайты, боты, CRM, магазины)
и **дизайн** (разовые работы и брендбуки). Система закрывает полный цикл:
лид → проект → производство контента (умный календарь) → публикация → реклама → деньги (финансы)
→ зарплаты и KPI сотрудников.

### Стек
- **Бэкенд:** NestJS 10 + TypeORM + PostgreSQL (Supabase). JWT в httpOnly-cookie,
  refresh-токены, 2FA (TOTP), Helmet, rate-limit, журнал безопасности.
  В dev `synchronize: on`; на проде `synchronize: off`, `migrationsRun: on` —
  новые таблицы/колонки создаются миграциями и идемпотентным DDL
  (`CREATE TABLE/ADD COLUMN IF NOT EXISTS`) в `onModuleInit` модулей.
- **Фронтенд:** React 18 + Vite + TypeScript, Tailwind (свой surface/primary-скейл,
  тёмная тема, персональные темы пользователей), @tanstack/react-query, Zustand,
  socket.io-client (живые обновления), lazy-роуты.
- **Интеграции:** Telegram-бот (уведомления + inline-кнопки действий),
  Email (SMTP), Google Gemini (ИИ-помощник), Meta Webhooks (приём событий Instagram/WhatsApp).
- **Деплой:** бэкенд — Railway (авто из main), фронтенд — Vercel. БД — Supabase Postgres.

### Сквозные принципы
- **RBAC**: роль + необязательная вторая роль (`secondaryRole`, права объединяются) +
  персональные гранты (`extraPermissions`) поверх ролей — выдаются на странице
  «Доступы сотрудников» и только расширяют доступ.
- **Уведомления в 3 канала**: in-app (колокольчик + WebSocket), Telegram, Email —
  для назначений задач, съёмок, дедлайнов, смен статусов, финансовых напоминаний.
- **Красный цвет** — только просрочки/ошибки/удаление; **зелёный** — только выполненное.
- Все списки живые: WebSocket-события (`projects:changed`, `workflow:changed`) +
  refetch по фокусу/интервалу как страховка.

## 2. Модули системы

### 2.1 Панель (дашборд)
Виджет «KPI команды» с кольцами процентов по каждому сотруднику и фильтрами по группам
ролей; периоды: Сегодня / Неделя / Месяц / Прошлый месяц. Спец-дашборды по ролям:
менеджеру продаж — воронка и его лиды, руководителям — сводка производства,
основателю — верхнеуровневые показатели.

### 2.2 Проекты
Типы: **SMM**, **Web сайт** (+ подтипы: Лендинг, Телеграм бот, CRM система,
Интернет магазин), **Дизайн**. У проекта: менеджер (любой сотрудник — «менеджер
проекта» назначается полем, отдельной роли нет), участники, статус
(Планируется/В работе/Завершён), прогресс, дедлайн, описание, файлы, задачи.
- **SMM-проект обязан иметь тариф** (Start/Business/Premium/Индивидуальный) —
  тариф задаёт месячный план: N рилсов, M постов/макетов, K сторис.
  На карточке проекта — бейджи «сделано/план» (рилсы, посты) по текущему контент-плану.
- **Бриф** SMM-проекта: анкета внутри проекта + публичная ссылка
  `/public/brief/<token>` для заполнения клиентом без логина.
- **Реклама**: кампании с бюджетом и датами; точка на карточке (зелёная — идёт, красная — нет).
- Риски, бюджет, перерасход, история активности.

### 2.3 Умный календарь СММ (производство контента)
Раздел **СММ**: «Умный календарь», «Сторисы», «Проекты». Единая система производства
контента — отдельное хранилище `content_plan_items`, не связанное с задачами доски.
- **Календарь** (месяц/неделя/день, непрерывный скролл) показывает публикации
  (рилс/макет) и задачи подготовки. Перенос даты — перетаскиванием.
- **Задачи подготовки создаются автоматически**: под рилс — «Съёмка», под пост —
  «Дизайн», на день раньше публикации, с клэмпом по началу цикла проекта. Двигаются
  независимо от родителя; при возврате родителя в «Не запланировано» — удаляются.
- **Цикл и норма проекта**: день старта цикла, норма рилсов/постов за цикл,
  сторис в месяц (0–100, по умолчанию 20). Дневная норма сторис = месячная / число
  дней месяца. «Не запланировано» — бэклог, из которого контент раскладывается по дням.
- **Панель дня SMM-специалиста** (главная): мини-месяц со счётчиками Рилс/Макет/Сторис
  по дням, детали выбранного дня — задачи с отметкой «готово» и карточкой сценария,
  степпер сторис по проектам.
- **Схема нагрузки** (`СММ → Проекты → Схема`): колонки по специалистам + «Не назначены»,
  перетаскивание проекта между специалистами (только руководство).

> Предыдущая реализация — глобальная доска-канбан из 10 этапов
> (`Контент-план → … → Реклама`) — удалена из интерфейса в сентябре 2026.
> Бэкенд-движок `workflow_cards` пока сохранён (история и KPI-метрика доставки).


### 2.4 Календарь
Задачи с дедлайнами, съёмки, дни рождения; админ/основатель/сооснователь назначают
задачи сотрудникам прямо из календаря (исполнителю — уведомление в 3 канала,
статус меняется из карточки, из календаря и из Telegram-бота кнопками
«✅ Готово / ▶️ В работу»; автору — уведомление о каждой смене статуса).
Глобальный **календарь публикаций**: при планировании контента и съёмок датапикер
показывает занятость дат по всем проектам (метки рилс/макет/съёмка, счётчик и
подсказка при наведении).

### 2.5 Отчёты, Аналитика, Архив, Риски, Время-трекер, Файлы
Отчёты сотрудников; аналитика по проектам/нагрузке; архив проектов и карточек;
реестр рисков; трекер времени; файлы проектов с загрузкой.

### 2.6 Сотрудники и доступы
Карточки сотрудников (должность, контакты, telegram, дата приёма, статус,
KPI-кольцо), назначение роли и второй роли (вторые роли — только исполнители;
привилегированные не назначаются второй). Страница «Доступы сотрудников» —
выдача персональных грантов (см. §4).

### 2.7 База клиентов (продажи)
Лиды с направлениями **smm** / **development**; воронка стадий, активности
(звонки, письма, встречи), онбординг новых клиентов менеджерами продаж.
Менеджер видит только лиды своего направления.

### 2.8 Финансы (порт «Fin System · WebRand», доступ — только по гранту `finance.manage`)
Подразделы: **Обзор / Доход / Расход / Транзакции / Инвентарь / Настройки**.
- **Счета** (Alif, Dushanbe City, Наличные…) со стартовыми балансами; категории
  доход/расход/перевод/накопление; операции журнала двигают балансы.
- **Доход** по направлениям:
  - *SMM* — помесячные циклы оплат по частям: «Часть 1» платится в день подписания,
    остаток («Часть 2») планируется автоматически со сроком **+20 дней**; при полной
    оплате цикла **якорь даты** сдвигается на день фактической оплаты (просрочка
    двигает следующий срок), авто-создаётся план следующего месяца и уведомление;
    отмена оплаты откатывает якорь и авто-планы. Дата контракта «катится» по месяцам,
    незакрытый цикл прошлого месяца виден в текущем. Напоминания «получить оплату /
    получить остаток», отсчёт дней до сроков.
  - *Development/Design* — матрицы «проект × месяцы» с плановыми платежами,
    частичной оплатой (сплит план/факт), правкой суммы и срока каждого плана;
    дизайн — разовые работы + брендбуки по месяцам.
- **Расход**: Зарплата (фонд, авансы, **бонусы по месяцам**, «к выплате = оклад +
  бонус − аванс − выплачено», группировка сотрудников по категориям с подытогами),
  Аренда и подписки (остаток к оплате тает по мере оплат, отметка «оплачено без
  списания»), Долги (график погашения по месяцам), Прочее.
- **Транзакции**: журнал с inline-редактированием + **календарь-вид** (операции
  карточками по дням месяца).
- **Инвентарь**: оборудование с датой покупки, ценой, сроком службы; **линейная
  амортизация** и остаточная стоимость по полным месяцам, статусы
  (в работе/ремонт/списано/продано), ответственные, серийники, гарантия.
- Экспорт/импорт JSON, полный сброс. Ежедневный крон напоминаний о сроках оплат.

### 2.9 KPI
Универсальные метрики: закрытые задачи, часы, соблюдение дедлайнов, дни активности.
**План сторис** — проекто-дни: план = дни × проекты специалиста (свои = менеджер,
участник или назначен через поле «SMM-специалист»), факт = дни, где его вклад > 0.
Метрика выдаётся SMM-специалистам (и роли `storymaker`, оставленной для совместимости).
Историческая метрика доставки по журналу доски (`unit_events`) сохранена в расчётах.
У менеджеров продаж — свои метрики: прогресс воронки, новые компании, холодные
звонки, личные письма, встречи. Нормы масштабируются на длину периода.
Общий процент — среднее по метрикам. Клик по метрике — детализация.

### 2.10 Прочее
ИИ-помощник (Gemini, ключ только в env), журнал безопасности (входы, действия),
SMM-тарифы (справочник планов), Meta-вебхук (`/webhooks/meta` — verify + приём
событий; verify-token только из env `META_VERIFY_TOKEN`, подпись запроса пока
не проверяется — добавить до подключения обработки лидов), Telegram-бот:
уведомления и кнопки статусов задач (`t:done/progress`).

## 3. Роли (21) — подробно

Роль хранится в `users.role`, вторая — в `users.secondaryRole` (права = объединение).
KPI и дашборд — по основной роли.

### Топ-уровень
| Роль | Ключ | Подробности |
|---|---|---|
| **Администратор** | `admin` | Полный доступ ко всему, КРОМЕ финансов (финансы — только по гранту). Управляет сотрудниками, ролями, доступами, настройками. |
| **Основатель** | `founder` | Всё как admin + **финансы нативно** + назначение сооснователей, «Доступы сотрудников», очистка доски. |
| **Сооснователь** | `co_founder` | Права основателя, включая финансы нативно. |

### Менеджмент
| Роль | Ключ | Подробности |
|---|---|---|
| **Руководитель SMM** | `smm_director` | Видит **все SMM-проекты** компании (создание/редактирование/удаление/архив, участники, смена менеджера — только SMM). Полное управление доской (все этапы), владелец этапа «Согласование с клиентом». Тарифы, команды, аналитика, отчёты, риски, сотрудники. Без финансов. |
| **Руководитель по видеографии** | `video_director` | Менеджерский уровень видео-направления: доска (владелец «Съёмки» вместе с видеографом), approve/return задач, аналитика, отчёты, риски, сотрудники. Получает уведомления о новых съёмках. |
| **Менеджер продаж (СММ)** | `sales_manager_smm` | Только SMM-направление: свои лиды (`direction=smm`), проекты типа SMM, онбординг клиентов, календарь, аналитика. KPI: воронка, компании, звонки, письма, встречи. Без доски. |
| **Менеджер продаж (Разработка)** | `sales_manager_dev` | То же для разработки: лиды `development`, проекты Web сайт/Лендинг/Телеграм бот/CRM система/Интернет магазин (создаёт с выбором подтипа). Без доски. |
| **Проект-менеджер (Разработка)** | `pm_dev` | «Тестировщик» направления разработки: видит **все dev-проекты** компании без членства, анализирует их и фиксирует недостатки задачами-замечаниями. Календарь, аналитика, отчёты. SMM/Дизайн-проекты — запрещены (403), **доска скрыта**, финансов и клиентов нет. |

### Производство (исполнители; владение этапом = кнопки и назначение на своём этапе доски)
| Роль | Ключ | Подробности |
|---|---|---|
| **SMM специалист** | `smm_specialist` | **Ключевая роль SMM-производства.** Видит все активные SMM-проекты агентства; ведёт контент своих (назначенных через поле «SMM-специалист», а также где он участник/менеджер): панель дня, умный календарь, контент-план, создание проектов. **Отмечает сторис — только по своим проектам.** KPI «План сторис». |
| **Сценарист / SMM-менеджер** | `scriptwriter` | Владелец «Контент-плана»: темы, сценарии, даты публикаций, подтверждение КП. |
| **Организатор** | `organizer` | Владелец «Организации» (подготовка съёмок: дата, локация, реквизит). Видит все SMM-проекты. Получает уведомления о съёмках. |
| **Видеограф** | `videographer` | Владелец «Съёмки»: снимает контент, отмечает готовность. Уведомления о новых съёмках всем активным видеографам. |
| **Монтажёр** | `video_editor` | Владелец «Монтажа»: собирает рилсы, двигает карточки дальше. KPI считает монтаж ему даже когда карточка ждала обложку. |
| **Дизайнер** | `designer` | Владелец «Дизайна»: макеты, обложки к рилсам (отдельная задача с зачётом в KPI). |
| **Контролёр качества** | `qa` | Владелец «Внутренней проверки»: принимает или возвращает на доработку (возврат с комментарием, повторный проход не задваивает KPI). |
| **Публикатор** | `publisher` | Владелец «Готово к публикации»: собирает материалы, публикует, отмечает дату. |
| **Таргетолог** | `targetologist` | Владелец «Рекламы»: запускает кампании (бюджет, сроки) на опубликованный контент. |
| **Сторисмейкер** | `storymaker` | ⚠️ **Роль упразднена (сентябрь 2026).** Сторис ведут SMM-специалисты. Ключ оставлен в системе для совместимости со старыми записями; новых сотрудников на неё не назначают. |

### Прочее
| Роль | Ключ | Подробности |
|---|---|---|
| **Разработчик** | `developer` | Исполнитель dev-проектов, где он участник: задачи, календарь, отчёты, файлы. Без доски. |
| **Сотрудник** | `employee` | Базовая роль по умолчанию: свои задачи/проекты (по членству), профиль, уведомления. |

## 4. Персональные гранты (поверх ролей)

Выдаются admin/founder/co_founder на странице «Доступы сотрудников»; расширяют доступ:

| Грант | Что даёт |
|---|---|
| `projects.view / create / edit` | Проекты: просмотр ВСЕХ / добавление / редактирование |
| `content-plan.create / edit` | Контент-план: добавление / редактирование позиций |
| `stories.manage` | Истории: чтение отметок по проектам (запись — только SMM-роли по своим проектам) |
| `clients.view / create` | База клиентов |
| `finance.manage` | Весь раздел «Финансы» |
| `analytics.view`, `reports.view` | Аналитика и отчёты |
| `employees.view` | Сотрудники |
| `tariffs.manage`, `risks.view`, `archive.view`, `calendar.view`, `ai.chat` | Настройки/инструменты |

## 5. Ключевые бизнес-правила (кратко)

1. SMM-проект без тарифа не создаётся; тариф определяет план контента и KPI-нормы.
2. Первый транш SMM-оплаты — в день подписания; остаток — через 20 дней; полная
   оплата сдвигает якорь цикла на дату оплаты; следующий план создаётся автоматически.
3. Производство контента ведётся в «Умном календаре»: задачи подготовки (съёмка/дизайн)
   создаются автоматически на день раньше публикации и живут своей датой.
4. Назначение задачи/съёмки = моментальное уведомление исполнителю в 3 канала;
   смена статуса = уведомление автору.
5. Финансы изолированы грантом `finance.manage` (нативно — только основатель/сооснователь).
6. Прод-схема БД меняется только идемпотентными DDL/миграциями (synchronize выключен).
7. Отмечать сторис могут SMM-специалист и руководство, и только по своим проектам;
   «свой проект» = менеджер ∨ участник ∨ назначен через `smmData.smmSpecialistIds`.
8. Дневная норма сторис = месячная норма ÷ число дней месяца (единая формула на
   фронте и бэкенде).
