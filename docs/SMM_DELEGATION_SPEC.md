# SMM-специалист: задачи команде производства и TikTok у проекта

Решение владельца 17.11.2026 (холст «SMM: задачи команде и соцсети проекта», версия 2 — упрощённая).

## 1. Задачи команде

### Кто кому
- SMM-специалист — роль `smm_specialist` основная ИЛИ вторая — ставит задачи:
  себе и активным пользователям с ролью (основной или второй) из
  `DELEGATE_ROLES = ['designer', 'producer', 'video_editor', 'videographer']`.
  Другим ролям — 403 «SMM-специалист ставит задачи дизайнерам, продюсеру, монтажёрам и видеографам».
- Проект: `null` (без проекта) или SMM-проект, где он специалист (`smmData.smmSpecialistIds`) или участник
  (`project_members`). Иначе 403.
- Остальные правила создания (дедлайн обязателен, scope, general и т.д.) — как сейчас.
- Свою поставленную задачу автор-SMM может править (название, срок, описание, исполнители — с теми же ограничениями) и отменять.

### Сдача и приёмка (без нового статуса)
Статусы остаются `new | in_progress | done | cancelled`.
- Исполнитель отмечает «Готово» → `done`, `completedAt` (как сейчас). Задачи от SMM-специалиста закрываются
  без обязательного файла-результата — как поручения от руководства (файл можно приложить).
  Автору уже уходит уведомление «Задача выполнена» в колокольчик и Telegram — проверить, что для автора-SMM тоже.
- **«Ждёт проверки»** = `status = done` И `reviewedAt IS NULL` И `completedAt >= now() − 14 дней` И автор ≠ исполнитель.
- **«Принять»** — `POST /tasks/:id/approve`: теперь разрешено и для задачи в `done` без `reviewedAt`;
  ставит `reviewedById`, `reviewedAt`, `acceptedOnFirstTry = (reworkCount = 0)`; исполнителю — уведомление «принята».
  Кто может: как сейчас (PM) ИЛИ автор задачи (createdById = actor, не исполнитель).
- **«Вернуть»** — `POST /tasks/:id/return { reason }` (reason обязателен, 1–1000 символов): из `done` или `in_progress` →
  `in_progress`, `completedAt = null`, `reworkCount + 1`, `returnReason`; исполнителю — уведомление + Telegram с причиной.
  Кто может: PM или автор задачи.
- `@RequirePerm('tasks.approve' / 'tasks.return')` не должен отсекать SMM-специалиста (проверить карту прав).

### API
```
GET /tasks/delegation/options?projectId=<uuid?>
  → { people: Array<{ id, name, avatar: string|null, role: string, inTeam: boolean }>,
      projects: Array<{ id, name }> }
  people — активные DELEGATE_ROLES, без самого actor; inTeam — в команде выбранного проекта
  (smmData.videographerIds / videoEditorIds / designerIds, участники проекта); сортировка: inTeam, затем имя.
  projects — SMM-проекты actor-а (не в архиве), по имени. Для не-SMM — 403.

GET /tasks/assigned-by-me   (есть) — добавить в каждую задачу: completedAt, reviewedAt, reworkCount,
  awaitingReview: boolean (правило «Ждёт проверки» выше), project { id, name } | null,
  assignees [{ id, name, avatar }] (как сейчас — если уже есть, не ломать).
GET /tasks/from-management  (есть) — теперь и задачи от SMM-специалистов (автор с ролью smm_specialist
  основной или второй), плюс те же поля: completedAt, reviewedAt, awaitingReview, createdBy { id, name, avatar }.
GET /tasks/review-count     → { count } — сколько задач actor-а ждут его проверки (для счётчика в меню).
POST /tasks                 (есть) — с ограничениями выше. Тело как сейчас: { title, assigneeIds, projectId|null, deadline, description?, priority? }.
POST /tasks/:id/approve     (есть) — расширено.
POST /tasks/:id/return      (есть) — расширено.
```
Новые GET объявить ДО `@Get(':id')`.

## 2. TikTok у проекта

- Instagram — всегда. TikTok у SMM-проекта включает/выключает: SMM-специалист своего проекта (как и остальной
  профиль — `assertSmmOwn`), руководитель SMM, основатель/админ. Продюсер — нет. Никаких уведомлений.
- **Действует с дня изменения.** `smmData.tiktokLog: Array<{ from: 'YYYY-MM-DD' (Душанбе), on: boolean, by: userId, byName: string, at: ISO }>`.
  - Пустой лог: состояние = `!tiktokOff` на всём периоде с `TIKTOK_FROM` (как сейчас).
  - Первая запись при `tiktokOff = true` и пустом логе: сначала засеять `{ from: TIKTOK_FROM, on: false, by: null, byName: null, at: now }`.
  - Повторное переключение в тот же день заменяет запись этого дня; если итог совпал с предыдущим состоянием — запись дня удаляется.
  - `tiktokOff` продолжаем писать = текущее состояние (совместимость).
- Нужна ли публикации с датой `d` отметка TikTok: `d >= TIKTOK_FROM` И не сторис И состояние на дату `d` = включён.
  Состояние на дату — последняя запись лога с `from <= d`; до первой записи — включён.
  В `common/tiktok.ts`: `tiktokOnAt(smmData, date)`, `tiktokOffRanges(smmData) → Array<{ from, to: string|null }>` (to — исключительно),
  с unit-тестами. Все места, где сейчас `tiktokOff`/`tiktokNeeded` (content-plan, smm-control SQL, профиль проекта,
  голосовой ассистент — grep), перевести на расчёт по дате (в SQL — через диапазоны выключения).
- Профиль проекта (`getSmmProfile`) отдаёт: `tiktok` (текущее), `tiktokHistory: [{ from, on, byName, at }]` (новые сверху),
  `tiktokPending: number` — публикации с датой < сегодня, которым TikTok нужен и не отмечен (за последние 60 дней).

## 3. Фронтенд

- **Страница «Задачи»** (`ManagementTasksPage` — кабинет поручений для всех, кроме руководителей разработки) —
  минималистичная, по макету: вкладки «Мне · N» / «Я поставил · N» (сегмент), группы
  - «Я поставил»: «Ждут вашей проверки» → «В работе» (просрочка — красным текстом срока) → «Готово» (свёрнуто, показать);
  - «Мне»: «Сделать» (new/in_progress по сроку, одна кнопка «Начать»/«Готово») → «Сдано, ждёт проверки» → «Готово» (свёрнуто).
  - строка: аватар, название в одну строку, «имя · срок». Без цветных плашек статусов.
  - Клик по задаче в «Я поставил»: на компьютере — панель справа, на телефоне — экран поверх; заголовок, «имя · проект · сдал(а) когда»,
    результаты (файлы/заметки задачи, если есть), «Вернуть» (раскрывает поле «Что поправить», обязательное) и «Принять».
  - Кнопка «+ Задача» — для SMM-специалиста.
- **Новая задача (SMM)** — `QuickTaskSheet`: модалка на компьютере, лист снизу на телефоне. «Что нужно сделать?»; «Кому» — кнопки
  с именами («Себе» первой, затем люди из options, команда проекта первой), мультивыбор; «Проект» — кнопки проектов + «Без проекта»;
  «Срок» — «Сегодня» / «Завтра» / «Через неделю» / «Дата…» (до 18:00 по умолчанию), подпись с датой;
  «+ Описание, файлы, срочно» раскрывает описание и «срочно» (priority high). «Поставить» неактивна без названия и исполнителя.
  Помнит последний проект и исполнителей (localStorage, try/catch). Открывается со страницы проекта с выбранным проектом.
- **Счётчик** на пункте меню «Задачи» — `/tasks/review-count`, если > 0.
- **SMM-проект** (`SmmProjectPage`): блок TikTok — «Instagram · всегда», переключатель TikTok для SMM своего проекта;
  подпись; при `tiktokPending > 0` — «N прошлых публикаций ещё ждут отметки TikTok»; «История изменений» раскрывается.
  Кнопка «+ Задача команде» (SMM своего проекта) открывает QuickTaskSheet с этим проектом.
- Мобильная версия всего: кнопки ≥ 44 px, главная кнопка закреплена внизу листа, без горизонтальной прокрутки на 390 px.

## 4. Бэкенд: уточнения реализации

- Правила делегирования — `backend/src/modules/tasks/task-delegation.ts` (DELEGATE_ROLES, isAwaitingReview).
  Проверка проекта и исполнителей включается, только когда задача уходит не только себе: задачу себе
  SMM-специалист ставит, как раньше (любой проект). Неактивный/несуществующий исполнитель — 400.
- Поручения без файла-результата и раздел «Мне» — список `TASK_GIVER_ROLES` = руководство + smm_specialist
  (`MANAGEMENT_ROLES` не расширен).
- Карта прав: `tasks.approve` / `tasks.return` — добавлен только `smm_specialist`. Другие авторы без PM-роли
  (менеджеры продаж, pm_dev) по-прежнему получают 403 от гарда, хотя `awaitingReview` / `review-count`
  считают и их задачи.
- «Вернуть»: из любого статуса, кроме `cancelled` (как раньше, включая `new`); кроме полей из §1 сбрасывает
  `reviewedAt` / `reviewedById` (чтобы после повторной сдачи задача снова «ждала проверки»). Ответ — прежний
  `{ id, status: 'returned', returnReason, title }`. Уведомления «принята» / «возвращена» (колокольчик + Telegram)
  уходят всем исполнителям очереди, кроме действующего.
- «Принять» уже сданную: `completedAt` не меняется, отчёт за день повторно не создаётся.
- `assigned-by-me` / `from-management`: у каждого элемента `assignees` к прежним полям
  (`position, userId, isDone, doneAt, note, user{id,name,email,avatar}`) добавлены плоские `id, name, avatar`;
  у задач без строк очереди `assignees = []` — исполнитель в `assignee`. `project` — `{ id, name, projectType,
  status, isArchived, color }` или `null`.
- `GET /tasks/delegation/options` закрыт `tasks.create`; `inTeam` считается только для своего проекта из `projects`.
- `tiktokPending`: не отменённые публикации (не сторис, не карточки подготовки) с датой в [сегодня − 60, сегодня),
  без `tiktokAt`, которым TikTok нужен на их дату — независимо от статуса Instagram.
- Продюсер, приславший `tiktok` в PATCH smm-profile, молча игнорируется (как остальные не-производственные поля).
